# ԳԼՈՒԽ 3. ՀԱՄԱԿԱՐԳԻ ԾՐԱԳՐԱՅԻՆ ԻՐԱԿԱՆԱՑՈՒՄԸ

### 3.1 Ներմուծման և մշակման հոսքը Python notebook-ներում

Տվյալների մշակումը կազմակերպվել է Microsoft Fabric Python notebook-ներում։ Սկզբնական CSV ֆայլերը ներմուծվել են Lakehouse Files տարածք, ապա ուսումնասիրվել են աղյուսակների չափերը, սյունակների անվանումները, ամսաթվերի ընդգրկույթը և հիմնական դաշտերի առկայությունը։

Հիմնական ընթացքը ներառել է CSV ֆայլերի ընթերցում, orders/customers/order_items աղյուսակների միացում, վավեր պատվերների ընտրություն, customer_unique_id-ի կիրառում, ամսաթվերի և գների ստուգում, մաքրված գործարքների պահպանում Parquet ձևաչափով։ Մաքրված գործարքների ֆայլը պահպանվել է Silver շերտում՝ olist_valid_transactions.parquet անվամբ։

Հաջորդ notebook-ում ձևավորվել է դասակարգման տվյալային հավաքածուն՝ հաճախորդի նույնացուցիչով, snapshot_date-ով, 90-օրյա հատկանիշներով և հաջորդ 30 օրվա թիրախով։ Հավաքածուն պահպանվել է Parquet և CSV ձևաչափերով։

### 3.2 Սեգմենտավորման և դասակարգման մոդելների իրականացումը

Սեգմենտավորման համար հաշվարկվել են RFM հատկանիշները։ K-Means կիրառելուց առաջ թվային հատկանիշները մասշտաբավորվել են, քանի որ դրանց չափման միավորներն ու արժեքների տիրույթները տարբեր են։ Առանց մասշտաբավորման մեծ թվային տիրույթ ունեցող Monetary հատկանիշը կարող էր անհամաչափ ազդեցություն ունենալ հեռավորության հաշվարկի վրա։

Փորձարկվել են k=2-ից k=8 կլաստերային տարբերակները։ Դասակարգման համար համեմատվել են DummyClassifier ելակետը, Logistic Regression-ը և LightGBM-ը։ Մոդելների գնահատման ժամանակ դիտարկվել են Average Precision, ROC-AUC, Precision, Recall, F1 և confusion matrix չափանիշները։ Դասակարգման շեմը ընտրվել է validation տվյալների հիման վրա և դրանից հետո կիրառվել test հատվածի վրա։

### 3.3 MLflow փորձերը և մոդելների տարբերակավորումը

MLflow-ը նախատեսված է մեքենայական ուսուցման փորձերի պարամետրերի, չափանիշների և մոդելների արտեֆակտների գրանցման համար։ Fabric notebook միջավայրում MLflow tracking-ը գործարկվել է, և փորձերի համատեքստում գրանցվել են մոդելների համեմատության չափանիշներ։

Վերարտադրելիության համար յուրաքանչյուր փորձ պետք է կապակցվի տվյալների տարբերակի, հատկանիշների ցանկի, train/validation/test ամսաթվերի, մոդելի տեսակի, հիպերպարամետրերի և գնահատման չափանիշների հետ։ Մոդելը նպատակահարմար է պահպանել preprocessing քայլերի հետ միասին։ Ընթացիկ փուլում MLflow մոդելի լիարժեք գրանցումն ու production deployment-ը դեռ ավարտված չեն։

### 3.4 Խմբաքանակային կանխատեսումը և Power BI հաշվետվությունը

Համակարգի կիրառական վերջնական փուլում նոր հաշվարկային պահի համար պետք է կրկին հաշվարկվեն հաճախորդների հատկանիշները, կիրառվի պահպանված preprocessing-ը և մոդելը, ապա պահպանվի յուրաքանչյուր հաճախորդի կրկնակի գնման հավանականությունը։ Արդյունքային աղյուսակի առաջարկվող դաշտերն են՝ customer key, snapshot_date, segment_id, repurchase_probability, model_version և run_id։

Power BI հաշվետվությունը կարող է ներկայացնել սեգմենտների քանակը, RFM պրոֆիլները, գնման հավանականությունների բաշխումը և մոդելների գնահատման չափանիշները։ Այս փուլում Power BI հաշվետվությունը և ավտոմատացված կանխատեսման ամբողջական հոսքը դեռ ավարտված չեն։
